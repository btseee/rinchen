# D15 Tiny end-to-end pipeline: design

Status: binding for the D15 plan (`docs/superpowers/plans/2026-11-11-d15-tiny-pipeline.md`), written before the build; the last task of the plan amends it to the finished code (section 7, amendments, as D12's to D14's). The runbook is `docs/runbooks/15_tiny_pipeline.md`. Master plan: `docs/research/2026-10-29-rinchen-dev-agent-prompt.md`, milestone D15 and the definition of done in `<mission>`. Evidence for every number and every behaviour below: `.superpowers/sdd/2026-11-11-d15-tiny-pipeline/spike-findings.md` (a spike on this machine, CPU, offline; findings F1 to F18 are cited below), with the scripts in `.superpowers/sdd/2026-11-11-d15-tiny-pipeline/spike/`. Everything GPU-side, everything on GitHub Actions, any real corpus, model, generator or neural scorer, and the 4-core wall time are UNMEASURED and labelled so.

## 1. Goal and non-goals

Goal: one command, `rinchen tiny run --profile tiny` (the recipe `just tiny` calls it), that takes the committed fixtures through every stage of the project on the CPU with no network, no GPU and no model download, and writes `artifacts/tiny/report.json` (with `report.md` and a manifest) whose thresholds are the master plan's: every stage `ok` or `skipped` with a reason of a closed list, training-set chrF at least 50, Eole against CTranslate2 parity as D11, script purity 1.0, `placeholder_acc` 1.0 on the fixture, wall time at most 20 minutes. The stages: fetch (local fixtures), normalize and split, filter (the CPU stages, LaBSE and QE through planted stand-ins with `--qe-fake`), SentencePiece, the script converter, synthetic data from a fake chat server, the multilingual tiny model (Eole `build_vocab`, train, average), CTranslate2 float32 and int8 exports, parity, the service in process, robustness, evaluation, report. STOP gate (master plan: "CI runs `just tiny` green on 3.14"): the commands of the workflow, read from the justfile and `ci.yml` and run natively here on the CPU with the GPU hidden, are green and every threshold and every control behaves as the plan lists; "green on GitHub Actions" is UNMEASURED.

Non-goals:
- No new model code, no new metric and no mechanism an earlier milestone declined to build: no placeholder masking, no terminology engine (D12), no neural scorer (D13), no new decoder. The planted encoder of `--qe-fake` is a lookup table summed from fixed vectors, not a trained model, and ranks nothing.
- No network of any kind and no GPU: `rinchen data fetch`, `rinchen eval suite fetch` and `rinchen release hub --upload` are never run; the one socket is a loopback listener of the synth stage (P17). No docker. No FLORES+, no Inner Mongolian data, no Latin-written Mongolian, nothing else the project's content rules in CLAUDE.md exclude.
- No partial runs and no stage resume (P11): a rerun starts from nothing. No `--stages` or `--from-stage` option.
- No `full` run: `rinchen tiny run --profile full` is refused (P13); scale-up is each stage command with its own full configuration (P14).
- No release stage (`release stage` and `release hub`, D13) and no `rinchen maintain check` stage (P15). `just accept` stays a stub (P20).
- No edit of `pyproject.toml` or `uv.lock`; no new dependency.

## 2. Findings that bind the design (spike)

- F1 Every stage has a command or a library function that runs offline; the 25 CLI calls of the pipeline cost about 20 s of start-up of a total of 123 s; `rinchen data fetch` writes under the hard-coded `data/raw` and `rinchen filter run` cannot take a fake, so those two stages are library calls; a `local://` registry entry copies a file of the checkout.
- F2 The candidate fixtures are 68,056 bytes in 7 TSV files, deterministic to the byte, with the composition of P5.
- F3 The "1k" SentencePiece vocabulary is not reachable on templated text (ceiling 786 to 850, moving with the text); 640 is safe.
- F4 Filtering both directions of a pair flags the reversed rows as near-duplicates (185 of 1,450 at the default 0.8; datasketch refuses 0.99); filtered once per pair and expanded after, the default flags 3 of 760; the default length bounds flag 26 authentic rows, `{0.4, 2.5}` one. A planted-noise file gets exactly its expected reasons with the planted encoder (10 of 10), 4 of 760 authentic rows are flagged, 756 kept.
- F5 The converter chain is 45 s, deterministic, `cer 0.0285`, `word_accuracy 0.9160` over its 500 words.
- F6 The real `rinchen synth run` against a stdlib loopback chat server takes 1.3 s; `--no-qe` skips the GPU scorer and says so.
- F7 400 steps misses the threshold (chrF 27.4 to 48.6 per direction); 500 steps passes barely (56.2); 800 passes at 97.7; the robustness block is perfect at beam 1 from 1,000 steps in 15 of 15 exports (three seeds); 1,500 steps takes 44 to 57 s.
- F8 The decode of the thresholded runs must be greedy: at beam 4 one placeholder is lost in one export of nine and numbers and entities lose 2 to 30 rows; at beam 1 nothing is lost from 1,000 steps on, float32 or int8. `placeholder_acc` 1.0 holds only over rows the model trained on.
- F9 Float32 parity is 70 of 70 exact (mean |delta| 1.4e-6); the int8 export fails the exact-share rule on the same 70 held-out lines (64 of 68) and is indistinguishable from float32 on the memorised suites (chrF within 0.1).
- F10 The service runs in process through `TestClient` in 0.3 s of imports, 0.1 s of start-up and 30 ms of requests.
- F11 A fixture suite needs a split among `dev`, `devtest`, `test`: the memorised suites are split `test`, the held-out ones `devtest`, with no edit of `eval`.
- F12 Training, averaging, conversion and decoding are byte-deterministic across two runs in two directories; `created` stamps, the SentencePiece file (it embeds its paths) and every file that embeds `manifest_sha256` differ: the report embeds values and `model_sha256` only.
- F13 Four cores change little at 2 threads per run: 120.0 s under `taskset -c 0-3`; 23 MB of checkpoints dominate a 36 MB run directory; ARITHMETIC at the D14 factor 3: 370 s against a budget of 1,200 s.
- F14 `maintain check --no-drift --no-reruns` takes 14.4 s; the comparison that matters for a manifest, installed packages against the lock, is a 0.06 s library call; the runner, the signal handler and the commit protocol of D14 and D4 to D13 exist and are reused.
- F15 `ci.yml` has one job and a stub step named "(stub until D15)"; `nightly.yml` runs the same recipe and its static test holds the stub's name in a literal; `artifacts/` is not git-ignored; the uv shim of D14 lets a recipe body run from a temporary directory.
- F16 20,451 tests are collected (10 deselected); the D14 gate took 25 to 40 minutes.

## 3. Rulings

P1. Scope, names and layering. D15 builds `rinchen tiny run` (a typer group `tiny` with one command, replacing the stub `cli/tiny.py`; `cli/main.py` already registers it), the library `rinchen.tiny`, the configuration `rinchen.config.tiny` with `configs/tiny/tiny.yaml`, the Eole base config `configs/eole/tiny.yaml`, the fixtures `tests/fixtures/parallel/*.tsv` with their generator `scripts/build_parallel_fixtures.py`, the `tiny` recipe, a `tiny` job of `ci.yml`, the name of the nightly step, `/artifacts/` in `.gitignore`, and `docs/runbooks/15_tiny_pipeline.md`. Layering: `rinchen.tiny` imports the stage LIBRARIES (`acquire`, `text`, `split`, `corpus`, `filter`, `mine.embed`, `eval.suites`, `eval.robust_suite`, `eval.robust_spans`, `eval.segment_scores`, `serve`, `config`, `manifest`, `maintain.commands`, `maintain.lock`, `maintain.environment`, `errors`) and never a module of `rinchen.cli`, `train`, `synth`, `export`, `infer` (the CLI stages are subprocesses); the command modules `cli/tiny*.py` import `rinchen.tiny`, `cli.errors`, `cli.maintain_signals`, `manifest`; nothing imports `rinchen.tiny` but them. `rinchen.eval` imports nothing of `rinchen.tiny` (D13's scans unchanged). Edits to existing files, the only ones: `justfile` (the recipe), `.github/workflows/ci.yml`, `.github/workflows/nightly.yml` (one step name), `.gitignore` (+2 lines), `tests/unit/test_nightly_workflow.py` (the literal of the step name, forced), and additive entries of test lists (`tests/unit/test_cli_help.py` already lists `tiny`: no edit). Reason: a second copy of the orchestration of `eval run`, `export convert` or `train launch` would drift from the real commands, whose guards, manifests and exit codes ARE what the pipeline proves. Cost if wrong: a pipeline that imports a CLI module turns every refactor of the CLI into a pipeline break; a layering scan (Task 9) fails first.

The stages that write files use these directories under `--out-dir`, the closed list of P11: `01_fetch`, `02_corpus`, `03_filter`, `04_spm`, `05_converter`, `06_synth`, `07_train` (`prepare`, `train` and `average`), `08_export`, `09_parity`, `10_robustness`, `11_evaluate` (the suites and the runs) and `logs`; `environment` and `serve` write none. The decoded and scored artifacts are those of the real commands. Reason: the master plan's list, with the corpus expansion made explicit (F4) and the one stage the master plan lacks and the manifest needs (`environment`, P15). Cost if wrong: a stage renamed or reordered moves every key of the report; the ids are pinned by a test.

P3. Real binaries or library calls. A stage runs as the REAL `rinchen` command, `[sys.executable, "-m", "rinchen", ...]` through `rinchen.maintain.commands.SubprocessRunner` (own session, process group killed on a timeout or an interrupt, the output in `logs/<name>.log`, stdin closed), whenever a command exists that does the whole job from files; a stage runs as a library call in process only when no command can (the fetch writes under `data/`, the filter cannot take a fake, the corpus build has no command, the service is in process by the master plan, the synth fake server shares the orchestrator's process). The environment of a child is `child_environment(os.environ)` plus the threads: no `*_TOKEN`, `*_SECRET`, `*_PASSWORD` or `*_API_KEY`, `CUDA_VISIBLE_DEVICES=""`, `HF_HUB_OFFLINE=1`, `HF_DATASETS_OFFLINE=1`; the orchestrator runs inside `device_hidden()`. The results are read from the files a command wrote, never from what it printed (the one exception, the five lines of `convert-script eval`, are read from its log and checked by shape). Reason: isolation of signals, timeouts, logs and determinism, the exact guards the operator's commands have, and Eole and CTranslate2 are subprocesses anyway; the cost is about 0.8 s of start-up per command (F1). Cost if wrong: in-process calls would hide a defect of a command's own wiring; a call of a command whose output format moved fails by shape, with the stage named.

P4. The status model. A stage record is `(id, state, reason, detail)` with `state` in `ok`, `skipped`, `fail`; `reason` is None for `ok`, one of the CLOSED list of `rinchen.tiny.states` for `skipped` and `fail` (a function of integers for the failures: `exit code N`, `timed out after S s`, `the wall-time budget is spent`, `a check of the stage failed: <closed check id>`, `an input is missing or differs`); the constructor refuses a skip or a failure without one, as D14's `Step`. The skip reasons, written once: no language-identification model (GlotLID is a download); LaBSE and the QE scorer need models that were not downloaded (`--qe-fake` runs the planted stand-ins); no neural metric scorer (D13 built the seam of score files only; `--qe-fake` exercises the seam); the token-ratio check of the length filter needs a SentencePiece model that does not exist yet; an earlier stage failed. A stage with sub-parts (`filter`: `script_ratio`, `numbers`, `length`, `lid`, `minhash`, `labse`, `qe`; `evaluate`: `memorised`, `heldout`, `neural_seam`, `report`) lists their states in `detail.parts`; the stage is `ok` when no part failed, and a skipped part is a part skipped on purpose. The first failing stage ends the run: every later stage is `skipped: an earlier stage failed`, the report and the manifest are still written, the verdict is `fail`. Reason: the master plan's "all stages status ok or skipped-with-reason" with D14's closed-list discipline. Cost if wrong: a silent drop would read as health; a test asserts that the report lists every stage of P2 and every part, run or not.

P5. The fixtures. `tests/fixtures/parallel/` holds 7 UTF-8, LF, tab-separated files with a header line, made by `scripts/build_parallel_fixtures.py OUT_DIR` (self-contained: it embeds its nouns, entities and templates, imports only `rinchen.script_conv.rules.transliterate`, asserts Python 3.14, every language stream seeded from the text `7-<name>` so the files do not depend on the order of the draws) and committed byte for byte: `eng_Latn-khk_Cyrl.tsv` and `rus_Cyrl-khk_Cyrl.tsv` (`id, split, kind, <src lang>, khk_Cyrl`; 300 train, 15 dev and 30 test rows each: `base` 150/8/15, `int` 30/2/3, `decimal` 18/1/2, `grouped` 12/1/2, `placeholder` 60/2/5 over the ten indices `⟦0⟧` to `⟦9⟧`, `entity` 30/1/3), `mn_Mong.tsv` (`id, split, kind, mn_Mong, khk_Cyrl, eng_Latn`: 50 train, 10 dev, 10 test rows, each the traditional-script spelling, by `transliterate`, of a Khalkha sentence that the English pair file holds in the same split), `mono_khk_Cyrl.tsv` (64 Khalkha lines with their English oracle: the synthetic job's source), `noise.tsv` (10 planted pairs, `expect` naming the reason the filter must give: `script_tgt` 2, `len_ratio_char` 2, `numbers` 2, `duplicate` 2, `labse` 2), `nouns.tsv` (37 rows, three languages) and `entities.tsv` (20 persons and cities with their spellings): 68 KB in all, each file far under 2 MB. No sentence is in two splits, and none is in two files in any language except the `mn_Mong` rows (which copy, in the same split, the Khalkha and English sentences of an English-pair row) and the two `duplicate` noise rows (which repeat train rows on purpose); Khalkha is Cyrillic everywhere; nothing Inner Mongolian, no Latin-written Mongolian, no FLORES+. **What each part tests:** `train` rows are the model's data and the memorisation gate (the master plan's training-set chrF and `placeholder_acc` "on fixture"); `dev` rows are the validation lines of `train ablate` and the lines of `export parity`; `test` rows are the held-out report (chrF per direction, never gated, never used to choose anything: the pipeline selects nothing); the `mn_Mong` rows give the model a fifth direction, `mn_Mong-eng_Latn`, so that D12's `mong` section has a trained model to measure, and exercise SentencePiece coverage of the script (0.9923) and the `converted` arm; `mono` feeds the D6 job; `noise` gives the filter teeth (P6). The noise rows enter the corpus with the split `holdout`, so they are scored and counted and never trained on, whatever the filter finds. The profile pins the SHA-256 of every file and the pipeline refuses a changed byte (exit 3, nothing written); a unit test regenerates the files and compares bytes, pins the digest of the whole set (a new digest is a decision, not an update) and checks the composition above. Production code reads `tests/fixtures/` by the paths the profile names (as D1's registry entries `local://tests/fixtures/...` and D3's `configs/spm/tiny_1k.yaml` already do), never by import. Reason: F2, F7, F8: a fixture on which every number is attainable honestly and nothing is hidden. Cost if wrong: a fixture that is too hard makes the threshold fail (answer: more steps, P7), too easy hides regressions (the filter's planted noise and the held-out figures are the guard).

P6. The filter and its stand-ins. The filter stage runs `run_pipeline` over the PAIR corpus (one row per pair, F4), then expands every kept row of the splits `train` and `dev` (not `holdout`, not `test`) to both directions (the `mn_Mong` rows one way only) with `corpus_frame(..., created=<fixed stamp of the profile>)`. The stages that run, in order: `script_ratio`, `numbers`, `length` (`char_ratio {min 0.4, max 2.5}`, the token check `partial`), `minhash` (the default 0.8), `labse` and `qe` with `--qe-fake`; `lid` is skipped with its reason (P4). The two stand-ins of `rinchen.tiny.fakes`: `ConceptEncoder` (an `Embedder`: a bag of concepts, each concept a fixed pseudo-random unit vector seeded by its CRC-32, summed and normalised; concepts are the nouns of `nouns.tsv`, the entities and their traditional-script spellings, digit strings with their separators ignored, and the numbered placeholders) and `ConceptQE` (a `QEScorer`, `requires_cuda = False`, score `25 * (1 - cosine)`). No weight is trained and nothing is random at run time. Gates of the stage: with `--qe-fake` every planted row gets exactly its `expect` reason (10 of 10) and at most 1 % of the authentic rows are flagged (measured 4 of 760); without it the eight rows the CPU stages detect get theirs and the two misaligned rows are unflagged (and untrained: `holdout`). Reason: the master plan's `--qe-fake`, with a stand-in that can SEPARATE a good pair from a bad one so the stage has something to prove. Cost if wrong: a stand-in that rejects authentic rows shrinks the training set silently; its property tests (every authentic row passes, every planted row is caught, deterministic across processes and hash seeds) are the guard, and the count of kept rows is in the report.

P7. The model, its steps and its decode. `configs/eole/tiny.yaml` is the base config (the model of `configs/eole/teacher_tiny.yaml`: 2+2 layers, `hidden_size` 64, 4 heads, feed-forward 128, `SinusoidalInterleaved`, tag in the source, AdamW, Noam warmup 100, learning rate 0.5, dropout 0, label smoothing 0.1, 2,048-token batches, `compute_dtype: fp32`, `gpu_ranks: []`, `bucket_size` 1024, one worker; trained from random initialisation); the profile overrides `training.train_steps` and `training.valid_steps` through the matrix `overrides` (measured to merge over the base file, which holds `save_checkpoint_steps: 100` and `keep_checkpoint: 4`), a one-variant matrix (`tag_placement src`, `temperature 1.0`, `bt_ratio 0.2`, seed from `configs/profiles/<profile>.yaml`, `dev_max_lines 100`). **`train.steps` is 1,500, not the master plan's 400** (F7: 400 steps gives 27.4 to 48.6 chrF; the master plan's own rule is "increase steps in tiny.yaml, never lower the threshold"): 500 is the first count above 50 (56.2), the robustness block is perfect at beam 1 from 1,000 steps in all 15 exports of three seeds, and 1,500 is 1.5 times that first count, costing 44 to 57 s. **The decode of every thresholded run is beam 1** (`decode.beam_size: 1`, F8: greedy is the decode `export parity` compares, and at beam 4 a placeholder is lost in one export of nine). A threshold missed is answered by raising `train.steps` in the profile, never by lowering a bound. Cost if wrong: another CPU may flip a row; the margin (15 of 15 exports at 1,000 steps and above, three seeds) is the evidence, the gate records the digests and does not assert them.

P8. The thresholds, in `configs/tiny/tiny.yaml` and in `report.json` (`id`, `bound`, `value`, `verdict`, `detail`):

| Id | Bound | Value read from | Measured (spike) |
|---|---|---|---|
| `stages` | no stage `fail`; every skip has a reason of the closed list | the stage records | all `ok` or `skipped` |
| `train_chrf` | at least 50.0 | the least corpus chrF (`metrics.chrf` of `result.json`) over the five memorised directions of the int8 export at beam 1 | 99.36 (`p6`: the least of 99.36, 99.70, 99.84, 99.96, 100.0), 97.27 (`p4`, before the suites held only the rows the filter kept) |
| `parity_exact` | at least 0.95 | `parity.json` of the float32 export: `exact_share` | 1.0 (70 of 70) |
| `parity_delta` | at most 1e-3 | `parity.json`: `mean_abs_delta` | 1.4e-6 to 1.6e-6 |
| `int8_chrf_drop` | at most 1.0 | the largest (float32 chrF - int8 chrF) over the memorised directions | at most 0.0 (int8 equal or higher) |
| `script_purity` | at least 1.0 | the robustness block | 1.0 (596 rows) |
| `placeholder_acc` | at least 1.0 | the robustness block | 1.0 (236 of 236) |
| `wall_time` | at most 1,200 s | the monotonic clock of the run | 120 to 158 s here (P12) |

Reported, never gated (each with D12's floor beside it, labelled a reference): `numbers_acc` (1.0), `entity_acc`, `term_acc`, `mong_source_retention`, the held-out chrF and BLEU per direction (55 to 65 chrF), the agreement of int8 and float32 hypotheses, the filter counts, the parity of the int8 export. The master plan names two quality thresholds; adding gates it does not name would make the pipeline red for numbers nobody owns. Cost if wrong: a gate that cannot fail proves nothing; the controls of P18 make each of the seven fail.

P9. Parity and the int8 export. The parity gate is the float32 export: `rinchen export parity` (exact share at least 0.95 and mean |delta| at most 1e-3, the command's own rule and D11's). The int8 export, the product, is checked by `int8_chrf_drop` and by the agreement of its hypotheses with float32's over the memorised and held-out suites (reported); `export parity` is NOT run on it: its exact-share rule is about held-out lines, where a tiny model is not confident (64 of 68, exit 4, F9) and a verdict on those lines says nothing about quantisation. Reason: D11 held a quantised export to chrF and said the 1e-3 bound is a float32 bound. Cost if wrong: a quantisation that breaks the memorised sentences shows in the chrF drop at once.

P10. `report.json`. Schema `rinchen.tiny/1`, UTF-8, sorted keys, two-space indent, one final LF, built only from observations: `{schema, profile, qe_fake, verdict, inputs: {config_sha256, fixtures: {file: sha256}, lock_sha256}, stages: [{id, state, reason, detail}], thresholds: [{id, bound, value, verdict, detail}], blocks: {filter, synth, converter, train, parity, serve, robustness: {values, coverage}, memorised: [...], heldout: [...], int8}, unmeasured: [...]}`. `robustness.values` is D12's six-key block and `robustness.coverage` D12's coverage block beside it (D12 requires both); `memorised` and `heldout` hold per direction the rows, the chrF, chrF++ and BLEU and the statuses; `train` holds the steps, the number of training rows by direction and the digest of the averaged weights; `unmeasured` is a fixed list (a GPU, a real corpus, a real generator, neural scorers, GitHub Actions, the 4-core time). Excluded on purpose: any timestamp, any duration (the manifest holds them), any absolute path, any environment value, any secret, any line of another program's output, any `manifest_sha256`, `hypotheses_sha256` or digest of a file that embeds a path (the SentencePiece model, F12): what stays is path-independent, so **two runs on this machine, in two directories, give equal `report.json` bytes** (F12: the weights, both `model.bin` files and the hypotheses are equal). `report.md` is rendered from the parsed `report.json` alone (a heading with the verdict, the stage table, the threshold table, the held-out table, the unmeasured list); `rinchen tiny run` re-renders it and compares before it writes. The D13 report of the held-out runs (`11_evaluate/report/report.{json,md}`) is a separate artifact, named in the blocks and never embedded. Cost if wrong: a path or a time in the report would break the byte equality the gate checks, and leak a home directory into a CI artifact; the gate scans for both.

P11. The output directory, the commit protocol, resume and idempotence. `--out-dir` defaults to `artifacts/tiny` (relative to the working directory). An existing directory may hold at its top level only the names the command writes (`manifest.json`, `report.json`, `report.md`, `logs` and the stage directories of P2); any other entry is exit 2 that counts the entries and names none, nothing written (D14 F5; a leftover `*.part` counts, and the message says to delete it). The order: parse the options; load and hash the config, every fixture file, the Eole base config, the serve config, the words file of the converter and `uv.lock`, BEFORE any is read, and parse the bytes hashed (a file that changed in between is exit 2); take the code version once (`code_version()`, D14 F4); `begin_commit(out_dir, "tiny_run")` (a manifest of another stage is exit 3 and nothing is removed; the old manifest is removed FIRST); remove the stage directories and the two documents the run owns; run; write `report.json` and `report.md` whole (`replace_file`), then `manifest.json` LAST. There is no `--keep` (the run directory is the artifact and nothing is deleted when the run ends; on a runner it vanishes with the job, locally it is `rm -rf artifacts/tiny`). **A rerun after a kill, or after anything, starts from nothing**: the whole run is 2 to 3 minutes, a stage-level resume would need a manifest per stage, a digest chain and an invalidation rule for 15 stages to save seconds, and a half-reused directory is how a stale checkpoint gets reported as a result. The manifest (stage `tiny_run`): `inputs` (every file hashed above), `outputs` (the two documents and the files whose digests are the checkpoint hashes: the SentencePiece model, the averaged weights `model.00.safetensors`, the float32 and the int8 `model.bin`, the converter's `model.bin`), `config_sha256`, `seed`, `tool_versions` (EVERY name of the lock with its locked version, a name locked at several versions joined by `, ` in sorted order, plus `python`), `metrics` (`seconds.<stage>`, `rows.kept`, `train.steps`), `status` (each stage's state). Reason: the commit protocol of D4 to D14 and the CLAUDE.md rule that every resolved version and checkpoint hash is in a manifest. Cost if wrong: a manifest that vouches for a half-written run; the interrupt control of the gate (P18) shows none is left.

P12. The wall-time budget. The profile holds `budget_seconds` (1,200: the master plan's 20 minutes on a 4-core CPU; `--budget-seconds` overrides it) and a timeout per stage (priors, each at least three times the spike's time and at least 30 s: `environment` 30, `fetch` 30, `corpus` 60, `filter` 120, `spm` 120, `converter` 300, `synth` 120, `prepare` 120, `train` 600, `average` 60, `export` 120, `parity` 180, `serve` 60, `robustness` 120, `evaluate` 300). The clock is `time.monotonic()` from the first line of the run. Before each stage the remaining budget is read: none left makes the stage `fail` (`the wall-time budget is spent`) and ends the run; a child gets `min(stage timeout, remaining)` seconds, at least 1, and is killed with its process group when it passes; the `wall_time` threshold is `pass` iff the total is within the budget. The measured seconds go to the manifest, never to `report.json`. **The 4-core cost is ARITHMETIC and labelled so:** 123 s measured on this 20-core machine (120 s with the children under `taskset -c 0-3`, F13), times the D14 factor of 3 for a slower runner (UNMEASURED) is 370 s, a third of the budget. Cost if wrong: a runner five times slower than this machine would still finish at 615 s; the budget fails a run that is slower than ten times, which is a regression to chase, not to absorb.

P13. The command. `rinchen tiny run [--profile tiny|full] [--out-dir DIR] [--config FILE] [--qe-fake/--no-qe-fake] [--threads N] [--budget-seconds N] [--dry-run]`. `--profile` (default `tiny`) selects `configs/tiny/<profile>.yaml` and `configs/profiles/<profile>.yaml` (the seed, read from the hashed bytes of the second file: not through `config.loader.load`, which reads `RINCHEN_*` variables); `--config FILE` replaces the pipeline file (the gate's control profiles). **`--profile full` is exit 2**: "no pipeline configuration for the profile 'full' (configs/tiny/full.yaml): `rinchen tiny run` is the end-to-end run of the tiny profile; the full profile is run stage by stage (docs/runbooks/15_tiny_pipeline.md)". `--qe-fake` defaults to the profile's `qe_fake` (true in `tiny.yaml`). `--threads` (default 2, the profile's) is the OpenMP and MKL count of each Eole run and the threads of CTranslate2. `--dry-run` validates the config, hashes and checks the fixtures, prints the stage list with the argument list of every command and writes nothing. Exit codes: 0 the verdict is `pass`; 4 the verdict is `fail` (a stage failed or a threshold was missed: everything is written and printed, as `rinchen export parity` does); 2 a bad option, config or profile, a changed input, an output directory with foreign entries, `--device auto` anywhere (never offered); 3 a missing or unreadable fixture or a fixture whose digest differs from its pin, another stage's manifest in the output directory; 1 the output cannot be written; 130, 143 and 129 for SIGINT, SIGTERM and SIGHUP (`cli.maintain_signals.exit_on_termination_signals`; the runner kills the child's process group; no manifest is written, the old one was removed first). What the command prints is the stage lines (`<id>: ok`, `<id>: skipped (<reason>)`, `<id>: fail (<reason>)`), the thresholds with their values, the verdict and the three paths. Cost if wrong: an exit code that a CI step cannot tell apart; the codes are those of D14 and D13.

P14. Scale-up is a configuration change only (master plan mission item 7). Every number and path that differs between a tiny and a larger run is in the profile file read by the closed loader `rinchen.config.tiny` (the fixtures and their digests, the registry, the SentencePiece, filter, converter, synth, Eole base, serve and evaluation configs, steps, thresholds, budgets, timeouts); the code has no branch on the name of the profile (an AST scan of `rinchen.tiny` and `cli/tiny*.py` finds no comparison with a profile name), and the gate's control profile (`--config` with `train.steps: 400`) runs the same code and misses the threshold, which IS the master plan's "if missed, increase the steps in the profile". The tiny-to-full mapping is a table of the runbook, one row per stage, naming the existing full configuration each stage command takes (`configs/spm/student_64k.yaml`, `configs/eole/teacher.yaml` and `student_*.yaml`, `configs/serve/server.yaml`, `configs/data/sources.yaml`, `rinchen convert-script train --profile full`); a test loads each of them through the same loader its tiny counterpart uses. `configs/tiny/full.yaml` is not shipped: nothing measured could fill it, and a table of unmeasured priors that a command would run is how a 14-day GPU job starts by mistake. Reason: D5's precedent (`convert-script train --profile full` needs `--confirm-full`) and the master plan's own scope of `just tiny`. Cost if wrong: an operator who expects `--profile full` to work reads the refusal and the runbook table.

P15. The environment stage and `maintain check`. `just tiny` does NOT call `rinchen maintain check --no-drift --no-reruns` as a stage (D14's open question 9): CI runs `just doctor` before it, the nightly job runs the full check before it, and the check costs 14.4 s (12 % of the run, F14) for a verdict the pipeline can reach in 0.06 s. The first stage, `environment`, calls `maintain.environment.check_environment` over the lock and the installed distributions in process (no uv, no subprocess): a machine that is not the lock is `fail` (`<m> packages differ from the lock, <e> are not in it`, counts only) because the manifest would name the lock's versions as the run's. Reason: CLAUDE.md requires the resolved versions in the manifest, and a manifest that lists the lock's versions for another environment is false. Cost if wrong: a developer machine with a stray package fails the run with the fix in the message (`uv sync --frozen --group dev`); the nightly and the preflight remain the full check.

P17.
