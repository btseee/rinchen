# D9 Document-level translation: design

Status: binding for the D9 plan (`docs/superpowers/plans/2026-11-09-d9-document-level.md`). Written before the build; amended to the finished code by Task 6 (sections 1 to 7 now say what the code does, and section 8 lists every place the build differs from what was first written and why). Master plan: `docs/research/2026-10-29-rinchen-dev-agent-prompt.md`, milestone D9. Evidence for every Eole fact: `.superpowers/sdd/2026-11-08-d9-document-level/spike-findings.md` (a spike on this machine, Eole 0.6.4, CPU, toy data; scratch scripts named there).

## 1. Goal and non-goals

Goal: a model that translates a window of 2 to 4 consecutive sentences in one pass and keeps the sentence boundaries (`<sep>`-aligned output), built by CONTINUING the training of OUR OWN teacher on document windows, plus the inference-side chunker that splits a document into windows, joins them with `<sep>`, splits the output back and falls back to sentence-level translation when a window's output does not have the same number of segments. STOP gate: a tiny doc model, continued from the (averaged) tiny teacher, decodes `<sep>`-aligned output for at least 90 % of the dev windows, and the chunker returns exactly one translation per input sentence for every test document.

Non-goals:
- No GPU was used and none is claimed (the machine has one that the owner did not authorise). No real document corpus exists: the toy documents are templated sentences that test structure, not translation quality.
- No distillation (D10), no CTranslate2 export or serving (D11), no robustness suites (D12), no release evaluation (D13).
- No fine-tuning of anything but OUR teacher: a continuation starts from a checkpoint that OUR launcher wrote and OUR manifest vouches for, never from another model's weights.
- No target-side tag placement for documents (source placement only: untested otherwise), no mixing of sentence corpora into the doc run (the spike measured it lowers the alignment at 1,000 steps; the real recipe is left to the operator and unmeasured).

## 2. Findings that bind the design (spike)

1. Eole's vocabulary is the `src_vocab` file (tokens seen in the data plus the `prefix` specials), cut to `src_vocab_size` (default 32,768), NOT the SentencePiece vocabulary. The tiny teacher's `vocab.json` lacks `<doc>` and `<sep>`; continuing it on doc data is SILENT: both become `<unk>` and the alignment is 0.00. Appending the symbols at the END of a vocabulary file does not survive a `src_vocab_size` cut. `teacher.yaml` sets no `src_vocab_size`, so a 128k SPM model would be cut to 32,768 pieces (the rarest become `<unk>`).
2. Continuing from another run works: `training.train_from: <source>/step_N` with a NEW `model_path` and `src_vocab` file (it must exist; its content is ignored) and a NEW `data` section; the source directory is never written. `reset_optim: all` loads the weights only: fresh Adam state, the step counter restarts at 1 and the new YAML's explicit optimizer options win; with the default `none` the optimizer options come from the checkpoint and the new YAML's are ignored; `keep_states` crashes. Omitted optimizer keys are inherited from the checkpoint's config, so a continuation YAML must set them explicitly.
3. The `model:` section of the new YAML is merged over the checkpoint's with NO check: a wrong `heads` loads silently and is recorded in the new `config.json`; `hidden_size` mismatches assert; a deeper `encoder.layers` leaves the extra layer untrained.
4. An AVERAGED directory (no `optimizer.pt`) works as `train_from` under every `reset_optim` value (it always acts as `all`): continuing from the averaged teacher is the natural path.
5. Resuming a continuation run with the same `reset_optim: all` still set restarts at step 1 and repeats the warm-up (spike). Dropping the key does not help either (found with the real Eole in Task 3): Eole fills a key the YAML omits from the config recorded in the checkpoint, and a continuation's checkpoints record `all`, so a resume of a continuation must STATE `reset_optim: none`.
6. `<sep>` and `<doc>` are single pieces of the SentencePiece model; Eole's own `sentencepiece` transform gives exactly the pieces `sp.encode` gives (standalone `▁` before `<sep>` written in text; none for a `src_prefix` piece); `re.split(r"\s*<sep>\s*", decoded.strip())` splits any output robustly and the segment count equals the `<sep>` count plus one. `<doc>` as a `src_prefix` piece and `<doc>` in the text perform alike; the prefix is the project mechanism.
7. The `<sep>` alignment does NOT reach 0.9 within 400 CPU steps (best 0.77); continued from the teacher it reaches 0.97, 0.92, 0.99 at 600, 800 and 1,000 doc steps (single seed, noisy between checkpoints); from scratch 0.92 at 800. Failure modes: an early model ignores the source and emits a fixed segment count; windows of 4 lose a `<sep>`. Window chrF stays low (31 at 1,600 steps) long after the structure is right: gate on alignment only.
8. `filtertoolong` counts pieces after `sentencepiece` and `prefix` (the tag and `<doc>` count), defaults to 192 and is silent apart from a statistic line; `eole predict` has NO source-length limit (only 5,000 sinusoidal positions) and caps the OUTPUT at `max_length` (250) and `max_length_ratio` (2) with SILENT truncation, which makes later segments vanish: the chunker's piece budget must stay within the doc model's training length and the predictor's `max_length` must exceed the expected output.

## 3. Rulings

T1. Vocabulary invariant: every Eole vocabulary file contains every D3 reserved symbol (`rinchen.spm.symbols.user_defined_symbols()`, 118 symbols): after `eole build_vocab`, a shared helper (`eole_run.add_reserved_symbols`) appends the missing symbols (count 1) to `vocab.src`; `run_training` (D7, only when it is given `reserved_symbols`: the ablation passes them, D5's converter does not) and `launch` (D8, for a run that is about to train) call it; `prepare_variant` sets `src_vocab_size` to the SentencePiece model's piece count plus one (Eole's pad token) when the base config sets none and refuses a smaller explicit value, and `launch` refuses a config that STATES a `src_vocab_size` or `tgt_vocab_size` below that, so the appended lines are never cut. A teacher whose checkpoint vocabulary lacks a symbol a continuation needs is refused (T6), not continued.
T2. Windows. `docify` forms windows from rows with `doc_id` and `seg_idx`: per `(src_lang, tgt_lang, doc_id)` the sentences sorted by `seg_idx`; a window holds only sentences whose `seg_idx` are consecutive (a gap, which D4's filters can leave, ends the window); the document is named within its corpus, so the key is `(src_lang, tgt_lang, corpus, doc_id)` and a window never holds sentences of two corpora; window sizes are drawn deterministically from `[min_size, max_size]` (default 2 to 4) by a seeded hash of `(seed, doc_id, start)`; a window is shortened while its source or target would exceed `max_pieces` (counted with the tag and `<doc>`) and a sentence that alone exceeds it is dropped from the windows; a tail of one sentence is dropped. Every row of every input file is counted once under a reason (conservation, as D7), in the order they are tried: `not_<split>` (`not_train` for the training windows, `not_dev` for the validation ones), `filtered`, `excluded_origin` (only `auth` origins make windows), `no_doc_id`, `no_seg_idx`, `empty`, `line_break`, `contains_sep`, `duplicate_seg_idx`, `too_long`, `gap_single`, `tail`; the rest are in a window. Source and target windows join with a single `" <sep> "`, and have equal `<sep>` counts; a sentence that itself contains the literal `<sep>` is excluded (`contains_sep`, counted); a literal `<doc>` or direction tag inside a sentence is NOT guarded (SentencePiece would read it as the symbol).
T3. The doc corpora are plain text (`<direction>.doc.src/.tgt` with sidecars as D7's corpus files); the tags are Eole `prefix` configuration: `src_prefix` is `"<2xx> <doc>"` and `tgt_prefix` `''`. The validation corpus holds windows of the DEV documents (same windowing, fixed seed 0, at most `--dev-max-windows` per direction, those with the smallest ids), pre-tokenised as D7 does (`[tag, "<doc>", pieces...]` source, `pieces` target). Weights follow D7: temperature over the directions' window counts, integer weights summing to `weight_total`. `rinchen train docify` builds all of it plus a rendered continuation base config and a manifest; it trains nothing.
T4. Continuation provenance. `rinchen train launch --continue-from SOURCE` starts a NEW run from OUR OWN checkpoint: SOURCE is a complete `step_N` directory that is the FINAL step of a run (the directory with its `launch.json`, at most three levels above) whose `train_launch` manifest lists its four files with matching sha256, or an averaged directory whose `train_average` manifest lists its files with matching sha256 and whose `averaged_from.json` agrees with that manifest (at least two source checkpoints, the same directories and sha256 in the same order, the same weights); `rinchen train average` itself refuses a checkpoint directory that is not inside a run with a `launch.json`; anything else is a `ConfigError` naming what is missing (never a silent acceptance of a checkpoint of unknown origin; a manifest or record that cannot be read is a `DataError`). The guard is against mistakes, not against someone who writes a manifest and a record by hand. The launcher records `continued_from` (kind, path, sha256 of the weights, `config.json`, `vocab.json`, the source manifest and its stage) in `launch.json` and in the new manifest's inputs; the run identity includes the source's weights sha256, so a continuation cannot be silently re-pointed.
T5. Attempts of a continuation. The first attempt's rendered config is the base plus `train_from: <SOURCE>` and `reset_optim: all`; every later attempt (a resume of the continuation) is the base plus `train_from: <own step_N>` and `reset_optim: none` (stated: see section 8). `train_from` and `reset_optim` stay unknown/forbidden keys in every base config; the validator accepts them only through `validate_train_config(cfg, continues=...)` for the launcher's own first continuation attempt (`reset_optim` exactly `all`, `train_from` exactly the recorded source directory) and through `resumes=True, resumes_continuation=True` for a later one (`reset_optim` exactly `none`). `update_vocab` and `keep_states` are never allowed.
T6. Checks before the first continuation attempt: (a) the base config's `model` section must state every key of the architecture guard (hidden size, word-vec size, heads, feed-forward, encoder and decoder layers, position scheme) and `checkpoints.architecture_mismatch` must find none against the SOURCE `config.json` (a continuation must say which architecture it believes it continues); (b) the SOURCE `vocab.json` must contain every symbol the new data needs: `<sep>`, `<doc>`, every direction tag and `<bt>` found in the data section's prefixes; a missing symbol is a `ConfigError` naming them and saying that the teacher predates the vocabulary invariant (T1); (c) the new run's own optimizer options (`learning_rate`, `warmup_steps`, `decay_method`, `optim`, `adam_beta2`) must be explicit in the config (omitted keys would be inherited from the checkpoint; these five are the only ones checked, every other option the config omits is inherited too, see section 8); (d) the SOURCE directory is hashed before it is read and compared with its manifest; (e) the SentencePiece model the config states for both sides must have the bytes (sha256) of the copy Eole saved into the source directory (a source without a copy is refused).
T7. Chunking at inference (`rinchen.infer.doc_chunker`, pure functions over callables `count_pieces`, `translate_window`, `translate_sentence`): a document is a list of sentences; empty or whitespace-only sentences are passed through (their translation is empty), call no translator and END the window they are in (the sentences on either side of one are never in one window, as `docify` ends a run at any sentence it leaves out); a sentence is one line (`one_line`); the rest are chunked greedily into windows of at most `max_sentences` sentences whose source costs at most `max_pieces` pieces (the budget is 2 for the tag and `<doc>` plus `count_pieces` of the joined text, so a `<sep>` costs what the counter says; the caller passes the piece counter of its SentencePiece model); a sentence that does not fit alone is an `oversize` chunk and a sentence the windows around it left alone is a `single` chunk, both translated at sentence level; a window's output is split with the robust regex; a segment count that differs from the window's sentence count, or a right count with an empty segment, makes the WHOLE window fall back to sentence-level translation of its sentences (never a partial repair: the fallback is structural, the spike measured that it does not repair content); a sentence containing the literal `<sep>` is refused for the document (`DataError`, before anything is translated). The result has exactly one translation per input sentence, in order, plus `ChunkStats` (sentences, chunks, windows, aligned, fallbacks as window indices from 0, singles, oversize, empty). What the callables raise is never caught; a result of `translate_sentence` that holds `<sep>` is not checked (D11).
T8. `predict_tokens` gains `max_length` and `max_length_ratio` (validated; default None leaves Eole's defaults and writes nothing); the gate and the chunker scenario of the STOP gate pass `max_length` 128 (the length the doc model trained with) and `max_length_ratio` 0 (the ratio cap off), so that no output is cut before the model ends it. Eole's cut is still silent: the chunker's budget measures the SOURCE only (section 8).
T9. The gate measures alignment, not translation quality: alignment rate of the final checkpoint on the dev windows at least 0.9 for each window size after 2,500 continuation steps (1,000 did not suffice on the windows `docify` cuts, see section 8), where a window is aligned when its output has one segment per sentence and none is empty (the chunker's rule), reported per window size; the chunker gate: every test document gets exactly one translation per sentence with fallbacks counted; sentence-level chrF is reported, never gated.

## 5. Contracts (summary; the plan's tasks fix the details)

- `eole_run.add_reserved_symbols(vocab_file: Path, symbols: Sequence[str]) -> tuple[str, ...]` (the symbols it appended; idempotent; the bytes of the file stay, only the appended lines are new, written whole through a temporary file and a rename).
- `docify.docify(rows, *, spm_model, min_size=2, max_size=4, max_pieces, seed, split="train") -> DocWindows(frame, stats)` (`split="dev"` with `DEV_WINDOW_SEED` cuts the validation windows); `doc_source.read_corpus_rows(paths, splits=("train", "dev"))`; `DocStats` (the reasons of T2, `windows_by_size`, `pieces` min/mean/p95/max per side).
- `doc_corpus`: `build_doc_corpora(windows, data_dir) -> list[CorpusFiles]`, `planned_doc_corpora`, `doc_weights`, `doc_data_section(...)`, `write_doc_validation(...)`, `render_continuation_config(base, ...)`, `check_continuation_base(base)`.
- `continuation.verify_source(source: Path) -> SourceProvenance`; `continuation.check_continuation(cfg, provenance) -> None`; `launch(..., continue_from: Path | None = None)`; `LaunchResult` gains `continued_from`.
- `doc_chunker`: `chunk_document`, `join_window`, `split_output`, `one_line`, `translate_document`, `DocumentTranslation`, `Chunk`, `ChunkStats`.
- CLI: `rinchen train docify --corpus ... --spm-model ... --config configs/eole/teacher_doc.yaml --out-dir ... [--min-size 2 --max-size 4 --max-pieces N --temperature 1.0 --seed 1234 --dev-max-windows 1000 --weight-total 100 --dry-run]`; `rinchen train launch ... --continue-from SOURCE`. Exit codes and manifests as D7/D8 (stages `train_docify`; `train_launch` for a continuation records the source).

## 6. Tests and the gate

- Unit tests with fakes everywhere but Eole; property tests for the windows (conservation, determinism, consecutive `seg_idx`, size bounds, equal `<sep>` counts) and the chunker (round trip, one output per input, any callable that mangles counts triggers the fallback).
- STOP gate (integration, real `eole`, real binary, CPU): toy documents (`tests/support/tiny_parallel.py` extended with documents of 4 to 8 consecutive sentences, split by document); the sentence-level tiny teacher through `launch` (its vocabulary now holds the reserved symbols), `average --last 2`, `docify`, `launch --continue-from <averaged>` for 2,500 steps (about two minutes), then every window of 2, 3 and 4 consecutive sentences of the dev documents (804, overlapping, held out) through `predict_tokens`: alignment >= 0.9, per window size reported; the chunker over the test documents with the real model for windows and the averaged teacher for the fallback: one translation per sentence for every document; refusals: a continuation from a checkpoint without provenance (a bare step directory, and a run without its manifest), from a tampered file, from a teacher whose vocabulary lacks `<doc>` (simulated by a vocabulary without it) and with a config that omits an architecture key, each exit 2 with Eole not started; an interrupted continuation resumes with `reset_optim: none` (log shows the step continuing, not restarting).

## 7. Open questions, recorded as such

- Everything GPU-side, the real document data, the quality of doc-level translation and the best window size/mix with sentence corpora are unmeasured; the alignment numbers are single-seed toy numbers.
- A continuation records the SOURCE but Eole's own `config.json` records only its path: relocating the source breaks nothing, but the path in the new checkpoint's config names a place that may vanish.
- Whether the doc model should also keep translating single sentences (it was continued on windows only) is unmeasured; the chunker therefore takes the sentence-level fallback from a CALLABLE (the sentence-level teacher in the gate).
- The real-corpus doc workflow is unmeasured: the mix of document windows with sentence-level data, the window-size mix, the number of continuation steps and the learning rate of a real teacher (`configs/eole/teacher_doc.yaml` is a table of priors).
- The limits the reviews left open on purpose are listed in section 8 and in `docs/runbooks/09_document_level.md`.

- T1 as amended (Task 1, controller ruling): ALL 118 reserved symbols go into the vocabulary, not `<doc>` and `<sep>` alone. The spike's figure of 232 for the tiny teacher held only for those two. - `add_reserved_symbols` as built: the bytes of the file stay (a CRLF file keeps its CRLF, the appended lines end in LF, an LF is added first only when the file lacks one), a file that has no counts gets bare symbols, nothing is rewritten when nothing is missing, the permission bits are kept (a review minor: the rename had changed 0o640 to 0o664) and a symbolic link is replaced by a regular file. A file with no token (0 bytes, blank lines only) is a `DataError` (review I4: a truncated `build_vocab` had become 118 lines of reserved symbols and every real piece `<unk>`).
- T2 as amended: the document key includes `corpus` (review C1: D4 names a document after the file it came from, so two corpora can hold the same `doc_id` and both number `seg_idx` from 0; without the corpus a window joined or interleaved sentences of two corpora). `corpus` is in `REQUIRED_COLUMNS`, in the sort and the duplicate key; the window frame has no `corpus` column and a window id is `corpus.schema.make_row_id` of the joined texts, a content hash. `duplicate_seg_idx` keeps the first row by (id, source, target). `no_seg_idx` and `contains_sep` are reasons of their own, and the reasons are tried in the order of `exclusion_reasons(split)`. `docify` takes a `split` (`train`, or `dev` with the seed `DEV_WINDOW_SEED` = 0 for the validation windows); a tail is what remains of a run when fewer than `min_size` sentences are left, `gap_single` a whole run shorter than `min_size`; a budget-shortened window may hold one sentence (`windows_by_size` has the sizes 1 to `max_size`). `max_pieces` bounds BOTH sides of a window; the source counts the tag and `<doc>` (2 pieces) and both sides are counted on the joined text, so the piece U+2581 in front of a `<sep>` counts. Eole's `filtertoolong` also counts two boundary tokens of a target, so a caller passes at most `tgt_seq_length` minus 2. `read_corpus_rows` (review I1) pushes the split filter into the lazy scan, so the text of a test row is never decoded; such a row stays as one row with only `split` filled, which `docify` counts under `not_<split>`, so `rows_read` is the number of rows of the files.
- T3 as built: the corpora are `<out>/data/doc/<src>-<tgt>.doc.src`, `.tgt` and a `.json` sidecar (`corpus_files.write_corpus_files`, reused when unchanged); `doc_corpus` also has `planned_doc_corpora` (what a dry run weighs) and `check_continuation_base` (the base config reads, holds no corpora of its own and passes `validate_train_config`). `rinchen train docify` defaults: `--min-size 2`, `--max-size 4`, `--temperature 1.0`, `--seed 1234`, `--dev-max-windows 1000`, `--weight-total 100`. `--max-pieces` has a default AND a ceiling, `min(src_seq_length, tgt_seq_length - 2)` of the base config's `filtertoolong` (Eole's default 192 for a length the base leaves out); a larger value is a `ConfigError` (Eole would drop the longer windows without a word), and a split with no window at all is a `DataError`, exit 3, also in a dry run. It writes `<out>/data/doc/...`, `<out>/valid.src` and `valid.tgt`, `<out>/config.yaml` (absolute paths; its run files are `<out>/run/vocab.src` and `<out>/run/ckpt`, so `launch --run-dir <out>/run` fits) and, last, `<out>/manifest.json` (stage `train_docify`; the inputs are the base config, the corpus files and the SentencePiece model, hashed before they are read). Its metrics are dotted as D7's: `count.<name>` for the train rows and `count.dev.<name>` for the dev rows (`count.excluded.<reason>`, `count.windows_by_size.<n>`, `count.pieces.src.max`), `max_pieces`, `min_size`, `max_size`, `temperature`, `weight_total`, `dev_max_windows`, `corpora.files`, `valid.windows` and `weight.<corpus>`. D7's CLI helpers `reject_repeated_corpora`, `numbers_under` and `corpus_manifest_files` moved to `cli/train_common` (behaviour unchanged).
- T4 as built: `verify_source` matches each manifest entry to a file by its NAME (the manifest lists the paths the files had when it was written, and a run may have been moved), refuses a name two entries share, and for a step requires the entries to lie in a directory named like the source, which is how a step that is not the final one is told. The SHA-256 of each file is taken once, before any check reads the file, and kept; `check_continuation` reads `config.json` and `vocab.json` only through the digest it holds. An averaged source must hold no `optimizer.pt` and no shard besides the manifest's; its `averaged_from.json` must name at least two checkpoints that the manifest lists as inputs in the same order with the same SHA-256, and the weights it records must be the vouched ones (review I2); `rinchen train average` refuses a checkpoint directory that has no `launch.json` within three parents (a guard against a mistake, not against a forged record). `launch.json` is schema version 1 for a plain run (byte-identical to before D9) and version 2 for a continuation, with `continued_from` (`kind`, `path`, the SHA-256 of the weights, `config.json`, `vocab.json` and the manifest, `optimizer_sha256` or null, `manifest_stage`, `step` or null, `source_run` or null). The run identity of a continuation covers the kind and the SHA-256 of the source's weights, `config.json` and `vocab.json`, not its path nor its manifest. The manifest of the new run lists the source's files and its manifest as inputs and has the metrics `continued_from.kind` (0 step, 1 averaged) and `continued_from.step`. The same `--continue-from` must be given again to resume, extend or `--write-only` a run that has step directories, and the source is verified again then; a run found FINISHED is judged by its record and needs no source. The hash is not atomic with Eole's own read of the files.
- T5 and T6 (forced deviation, Task 3, found with the real Eole): the attempts after the first state `reset_optim: none`; they do not omit the key. Eole fills a key the YAML omits from the config recorded in the checkpoint, and a continuation's checkpoints record `reset_optim: all`, so an omitted key restarted the run at step 1 with the warm-up again (a "resume" of step 40 that ran 200 steps from step 1). The validator accepts exactly `all` with `continues=` and exactly `none` with `resumes_continuation=True`; a plain run carries no key. The same fact makes every option a continuation config omits be taken from the source's checkpoint, not only the five of T6(c): `max_grad_norm`, `label_smoothing`, `dropout`, the batch size, `weight_decay` and the rest are inherited when omitted and are not checked (review M2, left open on purpose: the shipped configs state them all).
- T6(e) (review I3): `check_continuation` compares the SentencePiece model the config states with the copy Eole saved into the source directory (the file the source's `config.json` names, `${MODEL_PATH}/<name>`) by SHA-256, because the vocabulary of the source is the pieces that model gave its data; a source with no recorded or no saved copy is refused naming it. The manifest does not vouch for the copy and `launch.json` does not record its hash. A relative path in the config is read from the working directory of `rinchen`.
- T7 as built (Task 4 and the fix wave): the budget is `PREFIX_PIECES` (2) plus `count_pieces(joined text)`; blank sentences pass through as `""`, call no translator and CLOSE the window they are in (the first version left a blank out and let its neighbours share a window; review M4 made it consistent with `docify`); an oversize sentence is a barrier; a window whose segment count matches but has an empty segment falls back too (beyond the first T7); a lone `single` chunk goes to the sentence translator, never to the window model; sentences are normalised to one line (`one_line`) for both translators. The module defines its own `<doc>`, `<sep>`, join and `PREFIX_PIECES` because `infer` must not import `train`; a test pins them equal to `train.doc_source`'s and `spm.symbols`'. Left open on purpose (review M5, M6, M11): the budget measures the SOURCE only and `eole predict` truncates a target silently, so a cut inside the last segment still counts as aligned (D11); a `translate_sentence` result that holds `<sep>` passes through; a literal `<doc>` or direction tag in a sentence is not guarded.
