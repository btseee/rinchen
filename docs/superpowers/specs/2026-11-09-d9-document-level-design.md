# D9 Document-level translation: design

Status: binding for the D9 plan (`docs/superpowers/plans/2026-11-09-d9-document-level.md`). Written before the build; the build amends it to the finished code (Task 6). Master plan: `docs/research/2026-10-29-rinchen-dev-agent-prompt.md`, milestone D9. Evidence for every Eole fact: `.superpowers/sdd/2026-11-08-d9-document-level/spike-findings.md` (a spike on this machine, Eole 0.6.4, CPU, toy data; scratch scripts named there).

## 1. Goal and non-goals

Goal: a model that translates a window of 2 to 4 consecutive sentences in one pass and keeps the sentence boundaries (`<sep>`-aligned output), built by CONTINUING the training of OUR OWN teacher on document windows, plus the inference-side chunker that splits a document into windows, joins them with `<sep>`, splits the output back and falls back to sentence-level translation when a window's output does not have the same number of segments. STOP gate: a tiny doc model, continued from the (averaged) tiny teacher, decodes `<sep>`-aligned output for at least 90 % of the dev windows, and the chunker returns exactly one translation per input sentence for every test document.

Non-goals:
- No GPU was used and none is claimed (the machine has one that the owner did not authorise). No real document corpus exists: the toy documents are templated sentences that test structure, not translation quality.
- No distillation (D10), no CTranslate2 export or serving (D11), no robustness suites (D12), no release evaluation (D13).
- No fine-tuning of anything but OUR teacher: a continuation starts from a checkpoint that OUR launcher wrote and OUR manifest vouches for, never from another model's weights.
- No target-side tag placement for documents (source placement only: untested otherwise), no mixing of sentence corpora into the doc run (the spike measured it lowers the alignment at 1,000 steps; the real recipe is left to the operator and unmeasured).

## 2. Findings that bind the design (spike)

1. Eole's vocabulary is the `src_vocab` file (tokens seen in the data plus the `prefix` specials), cut to `src_vocab_size` (default 32,768), NOT the SentencePiece vocabulary. The tiny teacher's `vocab.json` lacks `<doc>` and `<sep>`; continuing it on doc data is SILENT: both become `<unk>` and the alignment is 0.00. Appending the symbols at the END of a vocabulary file does not survive a `src_vocab_size` cut. `teacher.yaml` sets no `src_vocab_size`, so a 128k SPM model would be cut to 32,768 pieces (the rarest become `<unk>`).
2. Continuing from another run works: `training.train_from: <source>/step_N` with a NEW `model_path` and `src_vocab` file (it must exist; its content is ignored) and a NEW `data` section; the source directory is never written. `reset_optim: all` loads the weights only: fresh Adam state, the step counter restarts at 1 and the new YAML's explicit optimizer options win; with the default `none` the optimizer options come from the checkpoint and the new YAML's are ignored; `keep_states` crashes. Omitted optimizer keys are inherited from the checkpoint's config, so a continuation YAML must set them explicitly.
3. The `model:` section of the new YAML is merged over the checkpoint's with NO check: a wrong `heads` loads silently and is recorded in the new `config.json`; `hidden_size` mismatches assert; a deeper `encoder.layers` leaves the extra layer untrained.
4. An AVERAGED directory (no `optimizer.pt`) works as `train_from` under every `reset_optim` value (it always acts as `all`): continuing from the averaged teacher is the natural path.
5. Resuming a continuation run with the same `reset_optim: all` still set restarts at step 1 and repeats the warm-up: a resume of a continuation must drop `reset_optim`.
6. `<sep>` and `<doc>` are single pieces of the SentencePiece model; Eole's own `sentencepiece` transform gives exactly the pieces `sp.encode` gives (standalone `▁` before `<sep>` written in text; none for a `src_prefix` piece); `re.split(r"\s*<sep>\s*", decoded.strip())` splits any output robustly and the segment count equals the `<sep>` count plus one. `<doc>` as a `src_prefix` piece and `<doc>` in the text perform alike; the prefix is the project mechanism.
7. The `<sep>` alignment does NOT reach 0.9 within 400 CPU steps (best 0.77); continued from the teacher it reaches 0.97, 0.92, 0.99 at 600, 800 and 1,000 doc steps (single seed, noisy between checkpoints); from scratch 0.92 at 800. Failure modes: an early model ignores the source and emits a fixed segment count; windows of 4 lose a `<sep>`. Window chrF stays low (31 at 1,600 steps) long after the structure is right: gate on alignment only.
8. `filtertoolong` counts pieces after `sentencepiece` and `prefix` (the tag and `<doc>` count), defaults to 192 and is silent apart from a statistic line; `eole predict` has NO source-length limit (only 5,000 sinusoidal positions) and caps the OUTPUT at `max_length` (250) and `max_length_ratio` (2) with SILENT truncation, which makes later segments vanish: the chunker's piece budget must stay within the doc model's training length and the predictor's `max_length` must exceed the expected output.

## 3. Rulings

T1. Vocabulary invariant: every Eole vocabulary file contains every D3 reserved symbol (`rinchen.spm.symbols.user_defined_symbols()`): after `eole build_vocab`, a shared helper appends the missing symbols (count 1) to `vocab.src`; `run_training` (D7) and `launch` (D8) call it; `prepare_variant` sets `src_vocab_size` to the SentencePiece model's piece count when the base config sets none and refuses a smaller explicit value, so the appended lines are never cut. A teacher whose checkpoint vocabulary lacks a symbol a continuation needs is refused (T6), not continued.
T2. Windows. `docify` forms windows from rows with `doc_id` and `seg_idx`: per `(src_lang, tgt_lang, doc_id)` the sentences sorted by `seg_idx`; a window holds only sentences whose `seg_idx` are consecutive (a gap, which D4's filters can leave, ends the window); window sizes are drawn deterministically from `[min_size, max_size]` (default 2 to 4) by a seeded hash of `(seed, doc_id, start)`; a window is shortened while its source or target would exceed `max_pieces` (counted with the tag and `<doc>`) and a sentence that alone exceeds it is dropped from the windows; a tail of one sentence is dropped. Every row of every input file is counted once under a reason (conservation, as D7): kept in a window, `no_doc_id`, `not_train`, `filtered`, `excluded_origin` (only `auth` origins make windows), `empty`, `line_break`, `too_long`, `tail`, `gap_single`. Source and target windows join with a single `" <sep> "`, and have equal `<sep>` counts; a sentence that itself contains the literal `<sep>` is excluded (`contains_sep`, counted).
T3. The doc corpora are plain text (`<direction>.doc.src/.tgt` with sidecars as D7's corpus files); the tags are Eole `prefix` configuration: `src_prefix` is `"<2xx> <doc>"` and `tgt_prefix` `''`. The validation corpus holds windows of the DEV documents (same windowing, fixed seed), pre-tokenised as D7 does (`[tag, "<doc>", pieces...]` source, `pieces` target). Weights follow D7: temperature over the directions' window counts, integer weights summing to `weight_total`. `rinchen train docify` builds all of it plus a rendered continuation base config and a manifest; it trains nothing.
T4. Continuation provenance. `rinchen train launch --continue-from SOURCE` starts a NEW run from OUR OWN checkpoint: SOURCE is a complete `step_N` directory that is the FINAL step of a run whose `train_launch` manifest lists its four files with matching sha256, or an averaged directory whose `train_average` manifest lists its files with matching sha256; anything else is a `ConfigError` naming what is missing (never a silent acceptance of a checkpoint of unknown origin). The launcher records `continued_from` (kind, path, sha256 of the weights, `config.json`, `vocab.json`, the source manifest and its stage) in `launch.json` and in the new manifest's inputs; the run identity includes the source's weights sha256, so a continuation cannot be silently re-pointed.
T5. Attempts of a continuation. The first attempt's rendered config is the base plus `train_from: <SOURCE>` and `reset_optim: all`; every later attempt (a resume of the continuation) is the base plus `train_from: <own step_N>` and NO `reset_optim`. `train_from` and `reset_optim` stay unknown/forbidden keys in every base config; the validator accepts them only through `validate_train_config(cfg, continues=...)` for the launcher's own continuation attempt, with `reset_optim` exactly `all` and `train_from` exactly the recorded source directory. `update_vocab` and `keep_states` are never allowed.
T6. Checks before the first continuation attempt: (a) the base config's `model` section must state every key of the architecture guard (hidden size, word-vec size, heads, feed-forward, encoder and decoder layers, position scheme) and `checkpoints.architecture_mismatch` must find none against the SOURCE `config.json` (a continuation must say which architecture it believes it continues); (b) the SOURCE `vocab.json` must contain every symbol the new data needs: `<sep>`, `<doc>`, every direction tag and `<bt>` found in the data section's prefixes; a missing symbol is a `ConfigError` naming them and saying that the teacher predates the vocabulary invariant (T1); (c) the new run's own optimizer options (`learning_rate`, `warmup_steps`, `decay_method`, `optim`, `adam_beta2`) must be explicit in the config (omitted keys would be inherited from the checkpoint); (d) the SOURCE directory is hashed before it is read and compared with its manifest.
T7. Chunking at inference (`rinchen.infer.doc_chunker`, pure functions over callables): a document is a list of sentences; empty or whitespace-only sentences are passed through (their output is empty) and left out of the windows; the rest are chunked greedily into windows of at most `max_sentences` sentences and at most `max_pieces` pieces (the budget counts one piece per `<sep>` and the tag and `<doc>`), a sentence over the budget alone becomes a `oversize` chunk translated at sentence level; a window's output is split with the robust regex; a segment count that differs from the window's sentence count makes the WHOLE window fall back to sentence-level translation of its sentences (never a partial repair: the fallback is structural, the spike measured that it does not repair content); a sentence containing the literal `<sep>` is refused for the document (`DataError`). The result has exactly one translation per input sentence, in order, plus statistics (chunks, aligned, fallbacks with indices, oversize, empty).
T8. `predict_tokens` gains `max_length` and `max_length_ratio` (validated; default None leaves Eole's defaults); the doc evaluation sets `max_length` from the source length so truncation cannot hide a lost segment.
T9. The gate measures alignment, not translation quality: alignment rate of the final checkpoint on the dev windows at least 0.9 after 1,000 continuation steps (the spike: .99 continued, .95 with the tag in the text), reported per window size; the chunker gate: every test document gets exactly one translation per sentence with fallbacks counted; sentence-level chrF is reported, never gated.

## 5. Contracts (summary; the plan's tasks fix the details)

- `eole_run.add_reserved_symbols(vocab_file: Path, symbols: Sequence[str]) -> tuple[str, ...]` (the symbols it appended; idempotent; the file is rewritten atomically).
- `docify.docify(rows, *, spm_model, tag_for, min_size, max_size, max_pieces, seed) -> DocWindows(frame, stats)`; `DocStats` (reasons as T2 and `windows_by_size`, `pieces` min/mean/p95/max).
- `doc_corpus`: `build_doc_corpora(windows, data_dir) -> list[CorpusFiles]`, `doc_data_section(...)`, `write_doc_validation(...)`, `render_continuation_config(base, ...)`.
- `continuation.verify_source(source: Path) -> SourceProvenance`; `continuation.check_continuation(cfg, provenance) -> None`; `launch(..., continue_from: Path | None = None)`; `LaunchResult` gains `continued_from`.
- `doc_chunker`: `chunk_document`, `join_window`, `split_output`, `translate_document`, `DocumentTranslation`, `ChunkStats`.
- CLI: `rinchen train docify --corpus ... --spm-model ... --config configs/eole/teacher_doc.yaml --out-dir ... [--min-size 2 --max-size 4 --max-pieces N --temperature T --seed S --dev-max-windows N --weight-total N --dry-run]`; `rinchen train launch ... --continue-from SOURCE`. Exit codes and manifests as D7/D8 (stages `train_docify`; `train_launch` for a continuation records the source).

## 6. Tests and the gate

- Unit tests with fakes everywhere but Eole; property tests for the windows (conservation, determinism, consecutive `seg_idx`, size bounds, equal `<sep>` counts) and the chunker (round trip, one output per input, any callable that mangles counts triggers the fallback).
- STOP gate (integration, real `eole`, real binary, CPU): toy documents (`tests/support/tiny_parallel.py` extended with documents of 4 to 8 consecutive sentences, split by document); the sentence-level tiny teacher through `launch` (its vocabulary now holds the reserved symbols), `average --last 2`, `docify`, `launch --continue-from <averaged>` for 1,000 steps (about a minute), then the dev windows through `predict_tokens`: alignment >= 0.9, per window size reported; the chunker over the test documents with the real model for windows and the averaged teacher for the fallback: one translation per sentence for every document; refusals: a continuation from a checkpoint without provenance, from a tampered file, from a teacher whose vocabulary lacks `<doc>` (simulated by a vocabulary without it) and with a config that omits an architecture key, each exit 2 with Eole not started; an interrupted continuation resumes without `reset_optim` (log shows the step continuing, not restarting).

## 7. Open questions, recorded as such

- Everything GPU-side, the real document data, the quality of doc-level translation and the best window size/mix with sentence corpora are unmeasured; the alignment numbers are single-seed toy numbers.
- A continuation records the SOURCE but Eole's own `config.json` records only its path: relocating the source breaks nothing, but the path in the new checkpoint's config names a place that may vanish.
- Whether the doc model should also keep translating single sentences (it was continued on windows only) is unmeasured; the chunker therefore takes the sentence-level fallback from a CALLABLE (the sentence-level teacher in the gate).
