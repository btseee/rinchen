# D15 Tiny End-to-End Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command, `rinchen tiny run --profile tiny` (the recipe `just tiny`), that takes committed fixtures through fetch, normalize and split, filter (with the planted stand-ins of `--qe-fake`), SentencePiece, the script converter, synthetic data from a fake chat server, the tiny multilingual model (Eole `build_vocab`, train, average), float32 and int8 CTranslate2 exports, parity, the service in process, robustness and evaluation, and writes `artifacts/tiny/report.json` (schema `rinchen.tiny/1`), `report.md` and a manifest whose thresholds are the master plan's: every stage `ok` or `skipped` with a closed reason, training-set chrF at least 50, Eole against CTranslate2 parity as D11, script purity 1.0, `placeholder_acc` 1.0 on the fixture, wall time at most 20 minutes. Real binaries on the CPU, no network, no GPU, no model download; scale-up is a configuration change only.

**Architecture:** `config.tiny` with `configs/tiny/tiny.yaml`, `configs/eole/tiny.yaml`, `configs/data/sources.tiny_parallel.yaml` (the closed pipeline configuration); `tiny.states`, `tiny.context`, `tiny.thresholds` (stage records, closed reasons, the thresholds of P8); `tiny.fixtures` and `scripts/build_parallel_fixtures.py` with `tests/fixtures/parallel/*.tsv`; `tiny.corpus`, `tiny.fakes`, `tiny.data_stages` (the in-process stages: environment, fetch, corpus, filter); `tiny.commands`, `tiny.model_stages` (argument lists and readers of the CLI stages: spm, converter, synth, prepare, train, average, export, parity), `tiny.suites`, `tiny.eval_stages` (serve in process, robustness, evaluate); `tiny.report`, `tiny.report_markdown`; `tiny.pipeline` (the order, the runner, the budget); `cli.tiny`, `cli.tiny_inputs`, `cli.tiny_output` (the command); the `tiny` recipe, the `tiny` job of `ci.yml`; `tests/support/{tiny_run,tiny_gate,tiny_profiles}.py`.

**Tech Stack:** Python 3.14.10, pydantic 2, PyYAML, typer, polars, numpy, pytest + hypothesis; the real `rinchen`, Eole 0.6.4, CTranslate2 4.8.4, SentencePiece 0.2.1 and sacrebleu 2.6.0 only inside the commands that already exist; the standard library's `http.server` for the loopback fake server. No new dependency: never edit `uv.lock` or `pyproject.toml`.

## Global Constraints

(The constraints files are the full text; the binding lines.)

- CPython 3.14.x only (`uv run`); every script entrypoint asserts `sys.version_info[:2] == (3, 14)`. No new dependency. Every model trained from random init; `position_encoding_type: SinusoidalInterleaved` everywhere; no pretrained model, no fine-tuning.
- NO GPU (the machine's GPU is not authorised): every process of a test or measurement runs with `CUDA_VISIBLE_DEVICES=""` on the CPU, `device cpu`, `gpu_ranks: []`; `auto` is never offered; no `torch.cuda`, `get_cuda_device_count` or `nvidia-smi` anywhere (an AST scan in the gate); no docker.
- NO NETWORK: no fetch of a real source, no Hub, no model download, never `rinchen eval suite fetch` or `rinchen release hub --upload`, never `rinchen data fetch` (it writes under `data/`), never read `~/.sacrebleu`, `~/.cache/huggingface` or a token file; `HF_HUB_OFFLINE=1`, `HF_DATASETS_OFFLINE=1`, `UV_OFFLINE=1` in every gate environment and in the call literal of every helper that starts a real binary; a child never inherits `*_TOKEN`, `*_SECRET`, `*_PASSWORD`, `*_API_KEY`. The one socket the pipeline opens is the loopback listener of the synth stage (P17), bound to `127.0.0.1` only. NEVER run `rinchen maintain check` without `--uv <shim>` or `--no-drift`; never `uv lock`, `uv add`, `uv sync` that changes the environment, `pip`.
- Nothing under `data/` or `models/` from tests (`tmp_path` only; committed fixtures live under `tests/fixtures/` and are each under 2 MB); no `artifacts/` inside the checkout from a test (the gate runs the recipe in a temporary directory).
- Tests before code; numeric and exact gates are gates (never lower a bound, a floor or a threshold; a miss is answered with more steps in the profile). Never weaken, skip or delete a failing test. Text of a fixture, a hypothesis or another program's output is never quoted in a message, a log line of the library, the report or the manifest: a message names a stage id, a file name, a row index, a closed reason and counts.
- No FLORES+, no Inner Mongolian data or variety, no Latin-written Mongolian, nothing else the project's content rules in CLAUDE.md exclude, anywhere (code, docs, configs, fixtures, comments, tests, commit messages; say "the project's content rules in CLAUDE.md" if you must refer to them). Invisible, control, look-alike and traditional-script characters in `.py` files only through `chr(0x....)`; the TSV and YAML fixtures hold characters as text (audit and report them).
- Layering (P1, P19): `rinchen.tiny` imports no module of `rinchen.cli`, `train`, `synth`, `export`, `infer` (the CLI stages are subprocesses); `eval` imports nothing of `tiny`; no profile-name branch anywhere in `rinchen.tiny` or `cli/tiny*.py`. Source files under 450 lines, test files under 900. No timestamp, duration, absolute path, environment value or secret in `report.json` or `report.md`.
- D3 to D14 must not change behaviour. The ONLY edits to existing files: `justfile`, `.github/workflows/ci.yml`, `.github/workflows/nightly.yml` (a step name), `.gitignore` (+2 lines), `tests/unit/test_nightly_workflow.py` (the one literal the rename forces), `cli/tiny.py` (the stub is replaced), additive entries of test lists; Task 10 edits documents. List every existing file you changed, with the reason.

Gate: `uv run ruff format --check . && uv run ruff check --no-cache . && uv run mypy src && uv run pytest -m "not network" -q` (about 30 minutes and 20,451 tests at D14's tip: run it in the BACKGROUND with a timeout and poll with bounded waits, in parallel parts that cover every collected test exactly once when the load is high).
