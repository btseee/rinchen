# D14 Maintenance Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command, `rinchen maintain check`, that tells a maintainer or a scheduled job whether the machine is the stack the lock file names and the toolchain starts (the CPU doctor checks, `uv lock --check`, the installed packages against the lock), what `uv lock --upgrade --dry-run` would take within the constraints of `pyproject.toml` and which of that a recorded decision says not to take blindly (the drift table), and whether the golden and parity checks the project pinned still come out the same (cheap reruns every night, heavier ones every week); a report `maintain_report.json` with a Markdown summary and a manifest that records every resolved package version and the lock's SHA-256; `.github/workflows/nightly.yml`; and the runbook `14_maintenance.md` (the upgrade procedure, the rollback, what each failure means). Nothing upgrades, uploads, pushes, writes the lock, touches a GPU or reaches an index from a test.

**Architecture:** `config.maintain` with `configs/maintain/maintain.yaml` (the closed configuration: skipped doctor checks, the uv argument lists and bounds, the pin rules, the reruns with their cadences and bounds); `maintain.states` (the states and the closed lists of reasons), `maintain.lock` and `maintain.environment` (the lock as a table, the installed packages against it), `maintain.uv_output` and `maintain.drift` (the parser of a dry run and the classified table), `maintain.commands` and `maintain.reruns` (the runner seam, the JUnit reader, the rerun outcomes), `maintain.report`, `maintain.report_markdown` and `maintain.check` (the report, the Markdown, the order of the steps with every seam injected); `cli.maintain`, `cli.maintain_output` and `cli.maintain_doctor` (the command, the files and the manifest, the CPU doctor list); `.github/workflows/nightly.yml`; `tests/support/{maintain_fakes,maintain_project,uv_outputs,fake_uv,maintain_gate}.py` and `tests/fixtures/maintain/*`.

**Tech Stack:** Python 3.14.10, `tomllib` and `importlib.metadata` (standard library), pydantic 2, PyYAML, typer, pytest + hypothesis, `uv` 0.13.7 only as a subprocess behind the runner seam (never `--upgrade` outside a dry run, never in a test), Eole 0.6.4 and CTranslate2 4.8.4 only inside the reruns that already exist. No new dependency: never edit `uv.lock` or `pyproject.toml`.

**Spec:** `docs/superpowers/specs/2026-11-11-d14-maintenance-design.md` (binding; findings F1 to F17, rulings M1 to M19). Spike evidence: `.superpowers/sdd/2026-11-11-d14-maintenance/spike-findings.md` (every number, output and format the code relies on is there with the script that measured it; read it first), the scripts and logs in `.superpowers/sdd/2026-11-11-d14-maintenance/spike/` (`scripts/s12_drift_proto.py` the drift prototype, `work/samples/` the MEASURED and HAND-WRITTEN uv outputs, `work/draft/nightly.yml` the workflow draft).
